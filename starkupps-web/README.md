# StarKupps Web

Customer-facing storefront for **StarKupps** (Munger, Bihar) — cold coffee, hand-stretched
pizza and smash burgers. A mobile-first React single-page application.

Everything a customer sees comes from **starkupps-admin** over HTTP; this app has no
hardcoded menu. Auth and live menu sync run on Supabase.

## Stack

| Concern            | Choice                                                |
| ------------------ | ----------------------------------------------------- |
| Build / dev server | Vite 8                                                |
| UI                 | React 19, TypeScript (strict)                         |
| Routing            | TanStack Router 1 (file-based, lazy route components) |
| Server state       | TanStack Query 5                                      |
| Auth + realtime    | Supabase (`@supabase/supabase-js`)                    |
| Styling            | Tailwind CSS v4 via `@tailwindcss/vite`               |
| Components         | shadcn/ui (Radix primitives), Lucide icons, Sonner    |
| Animation          | Motion                                                |
| Validation         | Zod                                                   |
| Tests              | Vitest                                                |

## Requirements

- Node.js 20.19+ and npm 10+
- A reachable **starkupps-admin** instance (REST + tRPC)
- A **Supabase** project (same one the admin uses) for auth and realtime

## Getting started

```sh
npm install
cp .env.example .env.local   # fill in your values
npm run dev                  # http://localhost:5173
```

`.env.local` is git-ignored. Vite exposes only `VITE_`-prefixed variables to the browser,
and every one of them is inlined into the public bundle — **never prefix a secret with
`VITE_`**. All env access goes through `src/config/env.ts`; nothing else reads
`import.meta.env`.

| Variable                        | Required | Purpose                                                       |
| ------------------------------- | -------- | ------------------------------------------------------------- |
| `VITE_API_URL`                  | yes      | Admin gateway base URL. Empty ⇒ same-origin `/api/public`     |
| `VITE_ADMIN_URL`                | no       | Accepted alias for `VITE_API_URL`                             |
| `VITE_SUPABASE_URL`             | yes      | Supabase project URL                                          |
| `VITE_SUPABASE_ANON_KEY`        | yes      | Public anon key                                               |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | no       | Accepted alias for the anon key                               |
| `VITE_PORT`                     | no       | Dev server port (default 5173)                                |
| `VITE_PREVIEW_PORT`             | no       | Preview server port (default 4173)                            |
| `VITE_DEV_API_PROXY`            | no       | Dev proxy target for `/api` (default `http://localhost:3000`) |

The app degrades rather than crashing: with no Supabase credentials the menu still loads
over HTTP and sign-in surfaces a "not configured" notice.

## Architecture

```
src/
├── main.tsx              Entry point — mounts the router
├── router.tsx            Router factory
├── routeTree.gen.ts      Generated by the TanStack Router Vite plugin
├── app/
│   ├── providers.tsx     Query, auth, outlet, cart providers + toaster
│   ├── query-client.ts   Shared React Query client
│   ├── PageMeta.tsx      Per-route document metadata (React 19 hoisting)
│   ├── route-errors.tsx  404 and route-error boundaries
│   └── routes/           File-based routes
├── api/                  Services — no React
│   ├── client.ts         Typed fetch wrapper (timeouts, ApiError)
│   ├── public.ts         Public gateway endpoints (REST + tRPC fallback)
│   ├── supabase.ts       Shared Supabase client factory
│   └── realtime.ts       Realtime subscriptions
├── components/           Reusable UI
│   ├── ui/               shadcn primitives
│   ├── layout/           Header, SiteFooter
│   └── shared/           Pressable, EmptyState
├── features/             Business logic, each self-contained
│   ├── auth/             Validation + sign-in/sign-up UI
│   ├── cart/             Cart sheet, item sheet, sticky bar
│   ├── checkout/         Zod checkout schema
│   ├── content/          Trust, gallery, location sections
│   ├── instagram/        Feed, marquee hook, embed helpers
│   ├── menu/             Live menu query, category imagery, menu section
│   └── profile/          Account tabs, address + order history storage
├── state/                Global React context (auth, cart, outlet)
├── types/                Domain types shared across layers
├── utils/                Pure helpers (format, motion, storage, errors)
├── config/               env, site copy, query keys
└── assets/               Bundled images
```

**Dependency direction:** `app` → `features` / `components` → `state` → `api` / `utils`.
`api`, `utils`, `types` and `config` never import React or a feature.

### Conventions

- **Routes** — add a file in `src/app/routes/`. `__root.tsx` is the shell and must keep
  `<Outlet />`. `index.tsx` is `/`, `about.tsx` is `/about`, `users/$id.tsx` is
  `/users/:id`, `posts/{-$category}.tsx` is an optional segment. `routeTree.gen.ts` is
  generated — never edit it.
- **Path alias** — `@/*` → `src/*` (declared in `tsconfig.json` and `vite.config.ts`).
- **Styles** — design tokens live in `src/styles.css` (oklch, warm minimalism). Use the
  CSS variables; never hardcode colours in components.
- **Providers** — global state is registered once in `src/app/providers.tsx`. A route
  should not wrap itself in `CartProvider`, `AuthProvider` or `OutletProvider`.
- **Money** — every amount in the app is integer **paise**. Format with `inr()` from
  `@/utils/format`; the gateway converts to rupees.
- **Errors** — report through `reportError()` from `@/utils/errors`. Add `ApiError`
  handling rather than swallowing failures in components.

## Responsive design

The storefront is mobile-first: most visitors arrive on a phone, so base styles
target the smallest screen and `min-width` queries enhance upward. Breakpoints,
the layout tokens, the per-pattern rules (navigation, hero, menu, cart/checkout,
Instagram, forms, footer) and the image pipeline are all documented in
[`RESPONSIVE.md`](./RESPONSIVE.md). Read it before adding a page or section.

## Deployment

`npm run build` emits a fully static SPA in `dist/`. Host it anywhere — Netlify,
Vercel, Cloudflare Pages, S3 + CloudFront, or a plain static server.

Two things the host must do:

1. **History fallback** — rewrite unknown paths to `/index.html`, so deep links like
   `/account` and `/auth/update-password` resolve client-side. The router renders its own
   404 screen for genuinely missing routes.
2. **Long cache for hashed assets** — files under `assets/` are content-hashed and safe to
   cache immutably. `index.html` must **not** be cached, or clients keep loading an old
   route tree.

Set the `VITE_*` variables in the provider's dashboard before building. Vite inlines them
at build time, so changing them requires a rebuild.

## Data flow

The admin app is the single source of truth.

- **Menu, outlets, charges, coupons, orders** — fetched over HTTP from
  `VITE_API_URL/api/public/*`, with the tRPC `public.*` router as a fallback for gateways
  that have not exposed a REST route yet.
- **Live updates** — a single Supabase Realtime channel watches the menu tables. Realtime
  is an enhancement: the query also refetches on window focus and reconnect, so a
  realtime outage degrades latency rather than breaking the page.
- **Auth** — Supabase email/password with PKCE recovery links.
